# v0.1 验证计划：先验证可用性，再谈成长效果

**当前研究结果**：本项目尚未招募受试者，未测出任何有效性、转化率、准确率或可靠性数值。不能用 COM-B、CBT 或实施意向的既有研究效果代替本产品的效果。

## 研究 A：任务可用性（计划 n=20，非已完成）

对象：18 岁以上自愿测试者，覆盖非技术用户。每人完成：2 道情境题、1 次事件记录、1 条行动计划。单次测试约 20 分钟。

观察（记录分子/分母）:

- `completion_rate`：完整做完 3 个任务的人数 / 开始人数。
- `fact_inference_error_rate`：把推测写为事实的事件字段数 / 抽查字段数（由两名独立审阅者按公开规则标注）。
- `mislabel_rate`：输出中出现永久人格定性或无证据数值评分的份数 / 输出总数。
- `comprehension_rate`：能正确解释“为何同一行为在不同情境下有不同效果”的人数 / 受测人数。

预设工程性验收目标（**非行业基线/非验证过的统计阈值**）：完成率 ≥70%；误将推测当事实 ≤15%；无证据贴永久标签 = 0。若达不到，优先修订提问、解释文字和规则，而不是加营销包装。

## 研究 B：连续使用与事件复核（计划 n=50，14 天）

选择自愿继续者，提供每 7 天一次的复盘；统计每位用户有效触发事件数、行动实际执行次数、未触发次数、事件条件差异和主动撤销画像次数。

至少报告：招募总数、同意人数、留存人数、失访人数、每个指标的分子分母及日期范围。

**不能**因为用户自评感觉更好，就断言系统提高了自控力、幸福感或解决了心理问题。若将来验证因果效果，需独立设计有对照的研究。

## 版本发布门槛

1. 12 张情境卡每张 ≥3 个合理选项，说明每项适用条件，且无隐含道德标准答案。
2. 至少 1 个虚构真实事件例子，事实/解释/未知明确分开。
3. 输出规则禁止从 1 次选择生成固定人格标签。
4. 所有对外成效声明都有可追溯的数据、样本量、日期、计算方法；无法验证时标为“尚未验证”。
5. 运行 `python3 -m unittest discover -s tests -v` 全部通过。

## 审核变更

公开问题、失败案例和反证；每次修改画像阈值、题卡或评分机制，都必须记录变更前后差异与原因。以后做的任何效果研究应在收集数据前登记主要指标。
